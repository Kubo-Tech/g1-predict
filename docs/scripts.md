# スクリプトリファレンス

すべてリポジトリルートから `python -m scripts.{名前} --race-code {16桁}` で実行する。引数は `--race-code` のみ。

**共通の注意**: 記事生成系はいずれも出力ファイルを**上書き**する。手で書き足した後に再実行すると編集内容は失われる。

| スクリプト | DB | TFJV | configs | templates | 出力 |
| --- | --- | --- | --- | --- | --- |
| `gen_trend` | ○ | − | `trends` | − | `傾向.md` |
| `gen_table` | ○ | − | `table` | − | `table/*.xlsx` |
| `gen_prev_day_trend` | ○ | − | − | − | `前日の傾向.md` |
| `gen_predict` | ○ | 読み | − | `TEMPLATE_PREDICT.md`, `points/` | `予想.md` |
| `gen_result_comment` | ○ | 書き | − | − | TFJV の `KEK_COM` |
| `gen_result` | ○ | 読み | − | `TEMPLATE_RESULT.md` | `結果.md` |
| `hatena_publish` | − | − | `hatena.yml` | − | はてなブログ記事 |

## gen_trend — 傾向分析記事

```bash
python -m scripts.gen_trend --race-code 2026061409030411
```

出力: `public/{開催年}/{race_code}_{レース名}/傾向.md`

処理:

1. `RaceGetter.get_race_shosai()` でレース名（`kyosomei_hondai`）と開催年を取得する。
2. `configs/{レース名}.yml` の `trends` を読み込む。**ファイルが無い場合や `trends` が空の場合は、見出し行だけの `傾向.md` を出力する**（エラーにはならない）。
3. `build_trend_sections()` が、カテゴリ（`出走馬傾向` / `騎手傾向` など YAML のキー）ごとに metric を集計し、Markdown テーブルへ整形する。
4. `# {レース名}{年}傾向分析` を先頭に、カテゴリセクションを連結して書き出す。

出力される表は次の形式（着度数は `1着-2着-3着-着外`）。

```markdown
### 枠順

| 枠順 | 着度数 | 勝率 | 複率 | 単回 | 複回 |
| --- | --- | --- | --- | --- | --- |
| 1枠 | 0-1-0-1 | 0% | 50% | 0% | 175% |

※過去10年阪神4日目良のみ
```

- 末尾の `※...` は metric に `condition` を指定したときだけ出る（[config-reference.md](config-reference.md#condition--開催条件の絞り込み)）。
- 各カテゴリの最後に空の `### 比較表` が挿入される。ここは手で埋めるためのプレースホルダ。
- 集計対象は既定で「対象レースと同じ特別競走番号・同一コースの過去10年」。

生成後は、各表の下に `> 一言コメント` を足したり、不要な表を削ったりして記事に仕上げる。

## gen_table — 出走馬分析表（Excel）

```bash
python -m scripts.gen_table --race-code 2026061409030411
```

出力: `public/{開催年}/{race_code}_{レース名}/table/{race_code}_{レース名}.xlsx`

処理:

1. `DataInterface.get_race_basic_info()` でレース名・開催年を取得する。
2. `configs/{レース名}.yml` の `table` を読み込む。**`table` セクションが無い場合は `KeyError` になる**（`trends` と違い、未定義は許容されない）。
3. `table` 直下のキーがシート名（例: `出走馬` / `騎手` / `生産者` / `種牡馬`）。
4. 各シートは、固定列（`枠` / `馬番` / `馬名`）＋ YAML で定義した列で構成される。
5. 出走各馬について `TableContext.get_value()` が `source.type` に従い値を取得する。
6. `openpyxl` で xlsx に書き出す。

書式:

- ヘッダー行は灰色塗り＋太字、`A2` で固定（`freeze_panes`）。
- `枠` 列は枠番に応じた JRA の枠色で塗る（`color_rules` は無視される）。
- それ以外の列は `color_rules` の先頭から評価し、最初に一致したルールの色で塗る。
- `display_map` があれば表示だけ変換する（色判定は変換前の値に対して行われる）。

分析表は記事にそのまま貼らず、スクリーンショットを `img/table/*.png` として貼る運用になっている。

## gen_prev_day_trend — 前日の傾向記事

```bash
python -m scripts.gen_prev_day_trend --race-code 2026061409030411
```

出力: `public/{開催年}/{race_code}_{レース名}/前日の傾向.md`

対象レースの**前日**に、同じ競馬場・同じ芝ダ区分で行われた平地レース（障害を除く）を集計する。土曜の馬場傾向から日曜のメインを読むための記事。

構成:

- `# {レース名}{年}前日の傾向`
- `## 出目` … 3着以内に入った馬を、人気・枠番・脚質・上がり順位のグループごとに頭数集計した表。
- `## 各レース` … レースごとの `### {競馬場}{R}R {条件} {距離}m {頭数}頭` と、3着以内の枠・馬番・人気・4角通過順・上がり3F・上がり順位の表。

前日に対象となるレースが1つも無い場合は、タイトル行だけの記事が出力される。

生成後は、馬場傾向の所感を書き足して仕上げる（実例: `public/2026/2026061409030411_宝塚記念/前日の傾向.md`）。

## gen_predict — 予想記事のベース

```bash
python -m scripts.gen_predict --race-code 2026061409030411
```

出力: `public/{開催年}/{race_code}_{レース名}/予想.md`

`templates/TEMPLATE_PREDICT.md` の各セクションを埋めて出力する。

| セクション | 生成元 |
| --- | --- |
| `## ポイント` | `templates/points/{レース名}.md`。無ければ空の見出しのみ |
| `## 関連記事` | 空。手で書く（傾向分析・前日の傾向の記事へのリンク） |
| `## 印` | TFJV の `UM*.DAT` から読んだ印 |
| `## 見解` | 印を付けた馬の過去走コメント（TFJV の `KEK_COM`） |
| `## 買い目` | 空。手で書く |

### 印セクション

`◎ ○ ▲ △ ◆ ☆ 注` の優先順（同じ印なら馬番昇順）に `{印}{馬番}{馬名}` を並べる。印は TARGET frontier JV 側で付けたものを読むだけで、このリポジトリでは印を決めない。

### 見解セクション

印を付けた各馬について、過去走を新しい順にたどり、TFJV に自分で書いたコメントがある走だけを列挙する。

- 同一レース（`race_code` の年＋レース識別部分が同じもの）は1度だけ扱う。
- 走数に応じて `前走` / `前々走` / `N走前` と表記し、そのレースのグレード（`G1` など）とレース名を付けて出力する。
- コメントが `[レース名] 本文` 形式の場合、レース名部分は分離して見出し的に使われる。

### 関連記事セクション

テンプレートの空セクションがそのまま出力される。`gen_predict` は何も埋めない。傾向分析・前日の傾向の記事は先に公開し、確定したはてなの URL を手で貼る。

## gen_result_comment — 結果の定型文を TARGET へ書き戻す

```bash
python -m scripts.gen_result_comment --race-code 2026061409030411
```

出力: `TFJV_DATA_DIR/KEK_COM/20{YY}/KC{競馬場}{YY}{開催コード}.DAT` への追記。

レース結果から各馬の1行コメントを作り、TARGET frontier JV の成績コメントファイルへ追記する。これを走らせておくと、以降のレースで `gen_predict` の見解欄に「前走 G1宝塚記念 0.3秒差5着。」のような行が自動で並ぶ。

生成される文字列:

- 通常: `[競走名略称6文字] {着差}{着順}着。`
  - 着差は2着以下ならその馬のタイム差、1着なら2着馬のタイム差を使う（例: `0.3秒差2着。`）。
  - タイム差が 0.0 の場合は着差コードを日本語化して `ハナ差` / `クビ差` のように表記する（`大差` / `同着` には「差」を付けない）。
- 取消・除外・中止・失格（異常区分コード 1〜4）: `[競走名略称6文字] {異常区分名}`

**追記専用**である点に注意。同じレースで2回実行すると同じ行が二重に入る。

## gen_result — 結果記事のベース

```bash
python -m scripts.gen_result --race-code 2026061409030411
```

出力: `public/{開催年}/{race_code}_{レース名}/結果.md`

`templates/TEMPLATE_RESULT.md` の `## 結果` と `## 回顧` を埋める（`## 総評` は空のまま。手で書く）。

- `## 結果` … 3着までを `{着順}着 {印}{馬番}{馬名}` で列挙する。
- `## 回顧` … TFJV の成績コメントがある馬について `### {着順}着 {印}{馬番}{馬名}` の見出しとコメント本文を出力する。
  - 正常に完走した馬を着順昇順で並べ、そのあとに異常（取消・除外・中止・失格）の馬を並べる。
  - コメント本文の `[レース名]` は除去し、`。` ごとに改行（行末2スペース）を入れて読みやすくする。

`gen_result` は TFJV のコメントを読むだけなので、**先に `gen_result_comment` でコメントを書き込むか、TARGET 上でレース回顧コメントを入力しておく**必要がある。

## hatena_publish — はてなブログ投稿

GitHub Actions（`.github/workflows/hatena-publish.yml`）から実行され、`main` への push で変更された `public/**/*.md` を投稿・更新する。ローカルから直接叩くことは通常ない。詳細は [hatena-publish.md](hatena-publish.md)。
